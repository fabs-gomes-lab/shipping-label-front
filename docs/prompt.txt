Crie um novo projeto frontend React do zero para consumir uma API Laravel de geração de etiquetas USPS. A configuração deve ser simples e mínima — apenas o necessário para rodar.
Referência visual (importante — ler antes de começar)
Na pasta docs/ do projeto existem quatro imagens de referência que definem o design e layout esperado das telas:

docs/login.png → referência para a página de Login
docs/listagem.png → referência para a página de Listagem de etiquetas
docs/forms.png → referência para a página de Criação de etiqueta
docs/detalhes.png → referência para a página de Detalhes da etiqueta

Antes de implementar cada página, visualize a imagem correspondente usando a ferramenta de leitura de arquivos. A implementação deve reproduzir fielmente:

Hierarquia e layout (posicionamento de elementos, agrupamento em cards/seções, alinhamento)
Tipografia (tamanho relativo entre títulos, labels e textos)
Espaçamentos (padding interno de cards, gaps entre elementos)
Componentes visuais (badges de status coloridos, cards de métricas, tabelas com bordas finas, botões primários vs secundários)
Ícones (usar ícones inline coerentes com o que aparece nas imagens — pode usar a fonte Tabler Icons via CDN, ou SVGs inline simples)
Paleta de cores (visual claro, bordas finas 0.5px, status purchased em verde, failed em vermelho, botão primário em azul claro)

Diretrizes gerais extraídas das referências:

Header consistente em todas as páginas: ícone + título à esquerda, ações à direita
Cards com border fina (0.5px) ao invés de sombras
Status como badge colorido com fundo claro e texto escuro da mesma família de cor
Botão primário sempre na cor de ação (azul claro), botões secundários neutros
Tipografia enxuta: 13px para dados de tabela, 14-15px para labels, 18-22px para títulos
Espaçamento generoso entre seções (~1.5rem)

Se algum detalhe não estiver claro nas imagens, faça a escolha mais simples e mencione no final.
Stack

React 18+ (mais recente estável)
TypeScript
Vite como bundler
React Router para navegação
Axios para requisições HTTP
npm como gerenciador de pacotes
Sem biblioteca de UI pesada — use CSS puro ou CSS Modules (sem Tailwind, sem Material UI, sem styled-components)
Sem gerenciador de estado externo (Redux, Zustand) — Context API + hooks bastam
Para ícones: Tabler Icons via CDN (<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@tabler/icons-webfont@latest/dist/tabler-icons.min.css">) ou SVGs inline simples


Passo 1 — Inicialização
Crie o projeto com Vite:
npm create vite@latest . -- --template react-ts
(ou em uma pasta chamada frontend se o diretório atual não estiver vazio — pergunte antes se houver dúvida)
Instale as dependências adicionais:
npm install react-router-dom axios

Passo 3 — CORS
O backend Laravel já está configurado com allowed_origins: ['*'], portanto qualquer origem é aceita. Nenhuma configuração adicional é necessária no frontend.

Passo 4 — Cliente HTTP
Crie src/services/http.ts com uma instância Axios:

baseURL vinda de import.meta.env.VITE_API_BASE_URL
Interceptor de request: anexa Authorization: Bearer <token> se houver token no localStorage
Interceptor de response: se vier 401, limpa o token e redireciona para /login
Timeout de 30s

Crie .env.example na raiz:
VITE_API_BASE_URL=http://localhost:8000/api

// Parcel no request usa number; no response o backend retorna string decimal ("10.00")
export interface ParcelRequest {

Passo 6 — Services (endpoints da API)
src/services/api/authService.ts:

login(payload: LoginRequest): Promise<LoginResponse> → POST /auth/login

src/services/api/shippingLabelService.ts:

list(page?: number): Promise<PaginatedResponse<ShippingLabel>> → GET /shipping-labels?page=N
get(id: number): Promise<ShippingLabel> → GET /shipping-labels/{id}
create(payload: CreateShippingLabelRequest): Promise<ShippingLabel> → POST /shipping-labels

src/services/api/healthService.ts:

check(): Promise<{ status: string }> → GET /health-check


Passo 7 — AuthContext
src/contexts/AuthContext.tsx:

Estado: user, token, isAuthenticated (derivado de !!token)
Persiste token no localStorage com chave auth_token e user com auth_user
Funções: login(email, password), logout()
Carrega token/user do localStorage na inicialização

src/hooks/useAuth.ts: hook que consome o context.

Passo 8 — Rotas
src/routes/ProtectedRoute.tsx: componente que verifica autenticação e redireciona para /login se não autenticado.
src/App.tsx configura as rotas:

/login → Login (pública)
/ → redireciona para /labels
/labels → LabelsList (protegida)
/labels/new → CreateLabel (protegida)
/labels/:id → LabelDetails (protegida)

Passo 11 — Endpoints da API (referência)
POST  /api/auth/login                    → { email, password } → { user, token }
GET   /api/shipping-labels?page=1        → lista paginada
GET   /api/shipping-labels/{id}          → detalhes com from_address, to_address, parcel
POST  /api/shipping-labels               → cria etiqueta
GET   /api/health-check                  → { status: "ok" }
Formato de erro padrão da API:
json{ "code": "ALGUM_CODIGO", "message": "Descrição do erro." }
Formato de erro de validação (422):
json{ "code": "API_002", "message": "Dados inválidos.", "errors": { "campo": ["mensagem"] } }
